# Try decision practice with an authored example

Open `/decision-practice` and choose **Try an example decision** before loading your own source. The two decisions use paper-registration diagrams: first inspect a visible reference, then reconsider what a mark should preserve when a sheet becomes wider. Retain a prediction, reveal the supplied account and record your own comparison. Missing sensory cues remain unknown. The app gives no correctness or physical-skill score.

**Save complete practice with frames** keeps the original example, retained PNGs and submitted responses together. Reopen that file through the existing complete-practice input. Personal demonstrations use the same source validation and action replay. The example action disappears after any source is accepted and cannot silently replace that work. An unavailable example can be retried; personal file inputs remain usable.

## What the example is

The pictures are authored diagrams drawn in code, encoded as a three-second WebM, then captured and exported through the unchanged Demonstration studio. The source clip is `/web/examples/decision-registration-authored.webm`. Its bytes and the original retained PNG identities are bound in the shipped bundle module. The supplied dimensions, purposes and accounts are authored, not measured expertise, contact, force or learning evidence.

The recorded seek requests are 0.25, 1.25 and 2.25 seconds; the actual browser-presented frames are 0.5, 1.5 and 2.5 seconds. These different times are preserved rather than relabelled. The reference and target have authored widths of 100 and 200 mm with the same supplied 10 mm left clearance.

The local data-only module uses the existing `script-src 'self'` policy. No connection permission or service dependency is added. It is admitted by the ordinary bundle reader; saved findings are recomputed.

## Recreate and inspect

From a source checkout with the existing Playwright, Chrome and FFmpeg tools, set `PLAYWRIGHT_PATH` and `CHROME_BINARY`, then run:

```sh
node tools/author-decision-example.mjs /absolute/path/to/checkout /fresh/output/directory
```

The generator creates a real clip and drives the maintained source studio. It retains the initial PNGs, clip, exported bundle, actual timestamps, hashes, screenshots and sandbox receipt. Review these outputs before replacing the shipped assets. Browser timing, PNG encoding and generated IDs may differ between runs; a regenerated bundle must keep its own original clip and frame identities. No user source is overwritten.
