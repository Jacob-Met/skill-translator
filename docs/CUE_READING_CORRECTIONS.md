# Transcript corrections and new inspections

This separate event account distinguishes correcting a recorded category from supplying another reading. A new reading retains its cue and provenance. A correction explicitly identifies the current revision, supplies a replacement category and states a reason. It cannot change the cue or origin. Every original event remains in the saved history; only the latest transcript for each reading enters the unchanged total-error comparison.

A correction is not verified cue truth and does not add independent evidence. Users who inspected again must record a new reading. Counts show active readings separately from retained events. Stale revisions, reused identities, foreign cues and malformed source anchors refuse before adoption. At most thirty readings and ninety events are admitted.

Browser receiving requires explicit BROWSER_HELPER, CHROME_BINARY, QA_OUTPUT and SOURCE_BUNDLE for `node tools/browser-reading-corrections.mjs`, with a new output directory and ordinary sandboxed Chrome.
