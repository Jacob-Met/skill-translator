# Contributing to SKILL TRANSLATOR

Use [the product seed](docs/PRODUCT_SEED.md) as an invention launchpad, not a fixed roadmap. Preserve the human benefit while discovering better approaches and unexpected useful abilities.

## Coordinate and reuse

- Read the [HAMON priority board](https://github.com/Jacob-Met/hamon/issues/1354), current source, issues, and pull requests. Record a concrete outcome and ownership; reconcile overlapping work before dependent edits.
- Check existing modules and their owners before duplicating algorithms. Prefer qualified reusable capabilities, clear interfaces, and actual consumer tests where they fit. Do not impose a shared platform, rewrite working products to satisfy an abstraction, or assume a similarly named component solves the same problem.
- Independent reads, experiments, reviews, and tests may proceed in parallel. Coordinate dependent writes, shared-interface changes, publication, and merges so one contributor does not overwrite another's work or rely on an unreceived change.

## Implement and integrate

- Use available normal-chat tools, authorized environments, and maintained HAMON receiving/execution/recovery helpers where useful. Check actual capabilities before declaring a blocker; do not assume Jacob's computer or a particular stack is required.
- Advance real capability and beneficiary outcomes alongside useful privacy, reliability, and accessibility work. Distinguish visible motion, inferred contact, measured force, simulation, physical execution, and demonstrated learning.
- Test changed behavior and meaningful failures; seek independent review, resolve findings, and use ordinary protections and authorized merge procedures. Verify maintained source and a relevant consumer when feasible. Report unavailable checks honestly.
- Preserve demonstration rights, consent, expert authorship, private learner information, and existing publication or hardware authority. Repository work does not itself authorize public releases, consequential physical actions, or contest submission.

## Continue inventing

After verified delivery, select **and begin** the next useful authorized improvement in the same execution when tools and capacity permit. Release completed claims, update evidence, and leave grounded opportunities without reserving speculative future chains. Do not wait for Jacob merely because one path is complete.

Let experiments, experts, learners, and better ideas reshape the product. Continuous contribution means useful ongoing work, not pretending runtime is uninterrupted or hiding a genuine blocker. A compelling first demonstration is neither the ceiling nor the finished assignment.
